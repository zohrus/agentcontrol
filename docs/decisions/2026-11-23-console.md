# Console: a terminal on the session's workspace (23 Nov 2026)

Code: `packages/relay/src/terminal/`, `packages/app/src/terminal/` and `api/terminal.ts`,
`packages/sdk/src/terminal.ts`, `packages/ui-template/src/terminal/`. Specification: the "Console"
blocks of `docs/plan.html` and `TASKS.md`.

## What Bun 1.4.4 offers (checked by running it)

`Bun.spawn(cmd, { terminal: { cols, rows, data, exit } })` starts the process on a pseudo-terminal
(`child.terminal.write / resize / close`; `stdout` and `stderr` are null). The child is a session
leader, so `kill(-pid)` reaches its whole process group. Types are in `@types/bun` 1.4.5. No
`node-pty`, no native dependency. It works inside the `bun build --compile` binary: the compiled
app smoke test has a step that opens a terminal and reads `echo` output (10 of 10 pass on Linux).
Not yet run on macOS (the mac CI job runs the same smoke).

## Decisions

- **Relay methods** `relay/terminal.open {sessionId, cols, rows}`, `.write`, `.resize`, `.close`;
  notifications `relay/terminal.data {terminalId, data}` and `relay/terminal.exit {terminalId,
  exitCode}`. Data is UTF-8 text, decoded with a streaming decoder so a character split across two
  reads is never broken. Output the shell wrote just before it ended is waited for (up to 200 ms).
- **Ownership.** A terminal belongs to the connection that opened it. Another connection asking
  for its id gets `terminalNotFound`, the same answer as for an id that does not exist. It ends
  when its connection ends, when the session is archived (`relay/sessions.archive` handler), and
  when the daemon stops (before the clients are disconnected, so they hear the exit). Ending is
  SIGHUP to the process group, SIGKILL after 1 s. At most 8 terminals per connection.
- **Shell and environment.** `$SHELL` of the relay's environment, `/bin/sh` when unset, started
  with `-l`. Tests inject `SHELL=/bin/sh` through the relay's environment. The environment is the
  relay's, minus `BUN_BE_BUN`, `BUN_INSTALL_CACHE_DIR` and every `AGENTCONTROL_*`, plus the
  session's `PORT` and `AGENTCONTROL_PORT_BASE` and `TERM=xterm-256color`.
- **Deviation: `portBase` in `session-created`.** The session's ports were not stored anywhere,
  so a terminal could not get `PORT`. `SessionCreatedPayload` has a new optional `portBase`
  (older logs and directory sessions lack it: no `PORT` then). Additive, nothing else changes.
- **ACP `terminal` capability stays off.** This is the user's console, not the agent's.
- **WebSocket** `GET /api/sessions/:id/terminal` on the app, JSON text frames (schemas in
  `protocol/src/terminal/socket.ts`): browser sends `open {cols, rows}` first, then `input` and
  `resize`; the app sends `data`, `exit` and `error`. One terminal per socket: closing the socket
  closes the terminal; the terminal ending (or the relay connection being lost) ends the socket.
  Frames over 1 MB are refused. Refused before upgrading: unknown session (404), archived (409),
  workspace offline (503), not an upgrade (426).
- **WebSocket authentication: the secret rides in `Sec-WebSocket-Protocol`.** A browser cannot set
  headers on a WebSocket, and the address is logged and kept in history, so the client offers two
  subprotocols: `agentcontrol.terminal.v1` and `agentcontrol.token.<secret>` (a base64url token is
  a valid subprotocol name). The root guard accepts the secret from that header only for a `GET`
  with `Upgrade: websocket`, and checks Host and Origin first, exactly as for every request, so a
  cross-origin page is refused with `forbidden-origin` even when it knows the secret, and a
  tokenless or wrong-secret request is refused with 401 before any socket exists. The app selects
  only `agentcontrol.terminal.v1`, so the secret is never echoed. Chosen over "secret as the first
  message" because no unauthenticated socket ever exists. The secret in the query string is not
  read. Tests: `e2e/terminal/access.e2e.ts`.
- **SDK** `client.terminal.open(id, {cols, rows, onData, onExit, onError})` returns
  `{write, resize, close}`; input typed before the socket is ready is queued in order; callbacks
  stop after `close()`.
- **UI.** A Terminal tab next to Changes, Editor and Preview, xterm.js 6.0.0 with
  `@xterm/addon-fit` 0.11.0 (exact, bundled stylesheet). The shell starts when the tab is first
  shown and keeps running while other tabs show (the tab content stays mounted, hidden). Sizes are
  fitted on resize and sent; colours come from the page's light/dark palette. When the shell ends
  the bar says so (exit code, or a plain-language problem) and "New terminal" starts another.

## Not done

- **Agent processes still inherit `BUN_BE_BUN` and `BUN_INSTALL_CACHE_DIR`** (the leak noted in
  `2026-11-23-release-layout.md`). Tried to scope them to the adapter launch only: `bun x` runs
  the adapter as a child that needs `BUN_BE_BUN=1` itself and passes its environment on; `--preload`,
  `BUN_OPTIONS`, `NODE_OPTIONS` and a global `bunfig.toml` either break the `x` subcommand or are
  ignored by it, so nothing can delete the variables before the adapter's own children start. A
  real fix needs the adapters installed by us and started with `bun --preload`. Left in `TASKS.md`.
  The terminal does not inherit them (tested).
- A terminal that survives an app or relay restart (tmux style) is a later question.
