# CI: what each job proves, and how to read a red run

Workflows: `.github/workflows/ci.yml`, `build.yml`, `audit.yml`, `release.yml`. The shared setup
(Bun, dependency cache, install, Playwright's Chromium) is `.github/actions/setup`.

| Job | Proves | Red means |
|---|---|---|
| ci / check | `bun run check`: every gate and the end-to-end suite with the coverage gate (audit is skipped) | Read the gate table at the end of the log: the row marked FAILED is the gate. `test:coverage` FAILED with "N of M runs passed" is a test failure, not a coverage failure. |
| ci / prove-gates | Each gate fails on a deliberately bad sample | A line "DID NOT FAIL <case>" names a gate that stopped working. The coverage case runs the whole suite, so it needs browsers, a git identity and full history, like `check`. |
| ci / gitleaks | No secrets in the history | The action prints the finding. |
| ci / coverage-stable (nightly) | Covered lines are identical run to run | A code path depends on timing. |
| audit (nightly, bun.lock changes) | `bun audit` | A known advisory in a dependency. |
| build / linux-relay | The compiled Linux relay answers `relay/hello` | Compile or runtime problem in the relay binary. |
| build / mac | Swift menu bar app builds for arm64 and x64; `make-app.sh` assembles the app; ad-hoc signature verifies; nested native code, binaries and bundle are ad-hoc signed (`codesign --verify --deep --strict`); the compiled app of the runner's architecture passes `scripts/smoke-binary.ts --app`, from the bundle and again from the mounted unsigned dmg | The step name says which stage broke. |

Unsigned release (owner decision, 23 Nov 2026): the mac job needs no Apple secrets and produces an
ad-hoc signed app and an unsigned dmg. `release.yml` signs and notarizes only when the secrets exist.

## Causes found

- `check` and `prove-gates` both failed on the same thing: the browser step ran `bunx playwright
  install` from the repo root, where bunx downloads the latest Playwright (a different Chromium
  revision than the pinned 1.63.0 the tests launch). It now runs from `e2e/`. `prove-gates` also
  had no browsers and no git identity, so its end-to-end run failed (exit 2) before the coverage
  gate could print the message the case expects, and it used a shallow checkout (no `origin/main`).
- `COVERAGE_BASE` (`github.event.before`) is now only set on main; on queue branches the gate uses
  the merge-base with `origin/main`.
- Scripts were not executable in git; workflows call them with `bash`.
- Action versions are pinned by SHA: actions/cache v6.1.0, actions/upload-artifact v7.0.2.
  Coverage upload uses `if-no-files-found: warn`.

## Known open

- The x64 app is built, signed and packaged on the arm64 runner but not run there (it needs Rosetta).
- macOS's temp folder is `/var/...`, a link to `/private/var/...`; `assertInside` compared a real
  and an unresolved path and refused the UI folder on a first start (found by the mac smoke test,
  covered by `e2e/app/data-folder-link.e2e.ts`).

## Red since the Console landed (926c5c0), found 23 Nov 2026

- `check` failed at `test:coverage` in every run from 926c5c0 on, with one failing file:
  `e2e/workspaces/ssh-terminal.e2e.ts` ("the terminal of a session on an ssh host is a shell on
  that host..."). Cause, proven by a raw capture of the runner's terminal: the runner's login bash
  is Ubuntu's, with systemd shell integration, which wraps every command's output in
  `ESC ] 3008 ; ... ESC \`. The shell ran the command and printed `here=...` right after such a
  sequence, and the helper's pattern only accepted a line start, a newline or a prompt before it.
  The helper now matches on the text a person reads, without control sequences (it also did not
  reproduce on dev machines, whose shells print none). A failed wait prints the last 400 visible
  characters the terminal showed.
- `prove-gates` showed `DID NOT FAIL coverage` for a different reason: the job never installed the
  OpenSSH server (only `check` did), so every ssh test failed, the suite exited 2 and the coverage
  gate never reached the message the case expects. A suite that cannot run is not a coverage
  failure, and the case rightly did not count it. The server is now installed by the `ssh` input of
  `.github/actions/setup`, used by every job that runs the suite.
- A red run now ends with its cause: `run-e2e` prints `FAILED <file>: <test names>` after the count,
  `check` repeats the last lines of each failed gate under the table, and `prove-gates` prints the
  exit code and last lines of every case that did not fail as expected.
